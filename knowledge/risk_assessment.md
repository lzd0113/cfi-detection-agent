# 风险评估标准

## 风险分级

### 高风险
满足以下任一条件：
1. **安全敏感模块**未开启 CFI：security、account、tee、useriam 模块的 .so 无 CFI
2. **大函数量无保护**：单个 .so 函数数 >10000 且 CFI 未开启（攻击面大）
3. **PAC 覆盖率极低**：AArch64 .so 的 PAC 覆盖率 <30%（ROP 防护薄弱）
4. **BTI 覆盖率极低**：AArch64 .so 的 BTI 覆盖率 <10%（JOP 防护薄弱）
5. **vcall 无保护**：vcall 调用点 >1000 且 CFI 覆盖率 = 0%（全部虚函数调用可劫持）

### 中风险
满足以下任一条件：
1. **核心模块覆盖率低**：arkui、graphic、communication、multimedia 模块的 CFI 覆盖率 <50%
2. **函数保护率低**：保护函数 / 总函数 < 5%（绝大多数函数无保护）
3. **vcall 覆盖率低**：vcall 调用点 >100 且 CFI 覆盖率 <30%（虚表劫持风险）
4. **PAC sign_only 比例高**：sign_only / (sign_only + protected) > 50%（签名未验证）
5. **关键库未保护**：IPC 相关（libbinder等）、网络相关 .so 无 CFI

### 低风险
满足以下任一条件：
1. **第三方库无 CFI**：thirdparty 模块的 .so（预编译，通常无法修改源码）
2. **预编译厂商库无 CFI**：libmali、librga、librockchip_mpp 等（闭源驱动）
3. **小函数量 .so**：函数数 < 50 且无 CFI（攻击面极小）
4. **纯数据 .so**：无可执行代码的 .so

## 模块风险画像

### 安全敏感模块（高优先级）
| 模块 | 说明 | 无 CFI 风险 |
|------|------|------------|
| security | 安全子系统（HUKS密钥管理、权限校验） | 密钥泄露、权限绕过 |
| account | 账户管理 | 账户劫持、认证绕过 |
| tee | 可信执行环境 | TEE 穿透 |
| useriam | 用户身份认证 | 指纹/人脸数据泄露 |

### 核心功能模块（中优先级）
| 模块 | 说明 | 无 CFI 风险 |
|------|------|------------|
| arkui | 方舟UI引擎 | UI 劫持、信息泄露 |
| arkcompiler | 方舟编译器 | 代码注入 |
| communication | 通信 | 中间人攻击、数据篡改 |
| multimedia | 多媒体 | 媒体解析漏洞利用 |
| distributeddatamgr | 分布式数据 | 数据泄露 |
| bundlemanager | 包管理 | 包篡改、权限提升 |

### 基础设施模块（中优先级）
| 模块 | 说明 | 无 CFI 风险 |
|------|------|------------|
| graphic | 图形 | GPU 利用、显示劫持 |
| hdf | 驱动框架 | 驱动漏洞利用 |
| startup | 系统启动 | 启动劫持 |
| powermgr | 电源管理 | DoS、电源状态篡改 |
| notification | 通知 | 通知伪造 |

### 低风险模块
| 模块 | 说明 | 无 CFI 风险 |
|------|------|------------|
| thirdparty | 第三方库 | 预编译，无法修改 |
| xts | 兼容性测试 | 非生产代码 |
| testfwk | 测试框架 | 非生产代码 |

## 评估规则

1. 优先检查安全敏感模块的 CFI 状态
2. 检查大函数量 .so 的保护状态（攻击面大小）
3. 检查 vcall/icall 调用点的 CFI 覆盖率
4. 对 AArch64 .so 检查 PAC/BTI 覆盖率
5. 区分"预编译无法修改"和"可修改但未启用"
6. 综合考虑模块在系统中的角色和攻击面
